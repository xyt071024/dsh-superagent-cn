破甲模式（Purge Mode）

← 返回首页 | 安装说明 | 完整文档

⚠️ 威胁提示（请先读这一段）

破甲模式会修改 DSH 宿主程序本身的行为。 这不是普通插件，它会：

  • 给宿主打 86 处补丁，改变模型行为边界
  • 绕过部分宿主内置的内容限制
  • 修改进程级配置

后果：

风险说明
行为不可预测模型可能输出你不期望的内容
升级会失效DSH 升级后补丁需要重新适配，否则插件打不开
数据风险输出内容不做过滤，可能包含错误信息被当真
合规责任在你用它做什么，责任完全由使用者承担
可能违反服务条款部分模型服务的条款禁止绕过限制

我们不做任何担保。 这是开源工具，按「现状」提供，作者不为使用后果负责。

建议：只在你自己拥有、你自己承担后果的环境使用。不要用在生产系统、不要用在别人的机器上、不要用于任何你需要向第三方负责的场景。

这是什么

破甲模式不是我们写的，是把两个开源项目集成进来：

项目作者仓库

本项目的定位：把它们打包成和 Super Agent 一致的两种形态（插件版 / 白板版），让安装体验统一。我们不是上游的官方发行版，也未获其背书。

它到底改了什么

上游的做法是在宿主代码里做精确替换——找到一段确切的代码，换成另一段。

项数量
宿主补丁86 处
状态自检25 层
依赖无（纯本地）

核心机制：DSH 每次启动时会读 ~/.dsh/prompt-inject.md（如果存在），把它作为系统提示的一部分注入。

破甲模式做的就是：往这个文件里写内容，并给宿主打补丁确保这段内容真的生效。

这意味着：

  • 文件删了，行为立刻恢复
  • DSH 升级，补丁可能需要重新打
  • 补丁与宿主版本强绑定，版本不对会失败

两种形态

和 Super Agent 一样，破甲模式也分两种：

形态是什么下载
插件版装进现有 DSHdsh-purge-plugin-v<版本>.tar.gz
白板版自带 DSH 的完整包dsh-purge-standalone-v<版本>-<平台>.zip

插件版安装

步骤 1：确认版本

这一步最容易出错。

dsh --version

必须落在 0.2.1-rc.1 / rc.2 / rc.3 / rc.5 / 0.2.2-rc.1 之一。

不在这个范围：不要装，先升级或降级 DSH。装错版本的表现是插件打不开或软件起不来。

步骤 2：备份

cp ~/.dsh/profiles/<你的profile>/cordis.patch.yml ~/.dsh/profiles/<你的profile>/cordis.patch.yml.bak-before-purge

必须做。 出问题就靠这个恢复。

步骤 3：创建独立 profile（推荐）

dsh purge --from-default-profile web --dump-config > /dev/null

为什么不装进现有 profile：破甲会改宿主行为，装进主 profile 会影响你所有其它插件。

步骤 4：安装

dsh plugin --profile purge add <破甲插件包路径>

步骤 5：启动并启用

dsh --profile purge

面板打开后，在侧栏找到 Purge / 破甲 入口，点「启用」。

它会给宿主打补丁。这个过程需要几十秒，期间不要关窗口。

步骤 6：验证

面板上应该显示：

补丁状态：86 / 86 已应用
自检：25 / 25 通过

如果不是 86/86：说明版本不匹配或权限不足，见下方排查。

白板版安装

下载

dsh-purge-standalone-v<版本>-<平台>.zip

解压

dsh-purge-standalone/
├── dsh.exe
├── node/
├── profiles/
│   └── purge/          ← 预配置
├── plugins/
├── prompt-inject.md    ← 破甲提示内容
├── 启动.cmd
└── README.txt

启动

双击 启动.cmd，或在终端：

./dsh --profile purge

首次启动会自动打补丁，等它显示 86/86。

恢复原状

快速恢复（推荐）

面板 → Purge → 「停用」

它会自动回滚补丁。

彻底恢复

# 1. 停用插件
dsh plugin --profile purge remove dsh-purge

# 2. 删除注入文件
rm ~/.dsh/prompt-inject.md

# 3. 恢复配置文件
cp ~/.dsh/profiles/<profile>/cordis.patch.yml.bak-before-purge \
   ~/.dsh/profiles/<profile>/cordis.patch.yml

# 4. 重启 DSH

白板版恢复

直接删文件夹。

故障排查

症状原因解决
插件打不开DSH 版本不在支持范围核对版本，升级或降级
补丁数不是 86/86宿主被改过，或有其它插件冲突换干净 profile 重装
启动就崩补丁与版本不匹配停用插件，恢复备份
打完补丁没效果提示文件没写进去 / 没重启检查 ~/.dsh/prompt-inject.md 是否存在，重启 DSH
白屏端口冲突或没带 token用终端打印的完整地址
Windows 权限错误文件被占用关掉 DSH 再装

版本不匹配怎么办

最稳的做法：装的和上游验证过的版本一致。

npm install -g @deepseek-ai/dsh@0.2.2-rc.1

然后重装破甲插件。

和 Super Agent 的关系

两件事，互不依赖。

Super Agent破甲模式
作用接到多源工作、自动干活改模型行为边界
装法独立 profile独立 profile
可以一起装吗可以，但各用各的 profile同左

同时装的话：两个 profile 分别起，互不干扰。

不建议把破甲装进 Super Agent 的 profile——Super Agent 有严格的权限设计（三层授权），破甲会削弱这层保护。

再次提醒

破甲模式会降低系统的行为约束。

如果你用它来处理：

  • 别人的数据
  • 生产系统
  • 需要向第三方负责的工作

请停下来想清楚。 出问题的责任完全在你。
