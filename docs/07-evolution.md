## 1. 四层进化

```
┌─────────────────────────────────────────────┐
│  L1 自检与复盘                                │
│  每次任务完成后回顾：哪里好、哪里慢、哪里错      │
└─────────────────────────────────────────────┘
                  ↓ 积累
┌─────────────────────────────────────────────┐
│  L2 经验固化                                 │
│  常用流程 → 技能；常见坑 → 检查清单            │
└─────────────────────────────────────────────┘
                  ↓ 优化
┌─────────────────────────────────────────────┐
│  L3 代码优化                                 │
│  发现冗余 → 提清理建议；发现死代码 → 提移除     │
└─────────────────────────────────────────────┘
                  ↓ 扩展
┌─────────────────────────────────────────────┐
│  L4 能力扩展                                 │
│  缺工具 → 装；缺知识 → 学（都要授权）          │
└─────────────────────────────────────────────┘
```

## 2. L1：自检与复盘

### 2.1 触发时机

| 时机 | 内容 |
|---|---|
| 任务完成 | 这次的完整复盘 |
| 任务失败 | 失败原因分析 |
| 定时（每周） | 汇总近期经验 |

### 2.2 复盘内容

```
1. 这次做对了什么？
   · 哪个判断准
   · 哪个方案有效
   · 哪个工具好用

2. 这次哪里慢？
   · 卡在哪个环节
   · 有没有多余的步骤
   · 上下文是不是读多了

3. 这次哪里错？
   · 判断失误在哪
   · 有没有返工
   · 用户有没有纠正

4. 下次遇到同类任务，应该怎么做？
   · 具体动作
   · 要避免什么
```

### 2.3 经验格式

```json
{
  "id": "lesson-001",
  "createdAt": "2026-11-10T23:00:00Z",
  "taskType": "code-modification",
  "context": "用户要求修改一个 React 组件的样式",
  "whatWorked": [
    "先读 AGENTS.md 再动手，避免违反项目规范",
    "改动前先跑一次测试，确认基线是绿的"
  ],
  "whatFailed": [
    "一开始没看清是哪个分支，改错了地方"
  ],
  "lesson": "动手前先确认当前分支，并检查目标文件是否在预期分支上",
  "appliesWhen": ["修改已有代码", "多分支项目"]
}
```

### 2.4 经验的使用

**不是每次都全量加载**（那样太贵）。而是**按任务类型检索**：

```
新任务到达
   ↓
识别任务类型（改代码 / 写文档 / 排查问题 / ...）
   ↓
检索相关经验（按 taskType + 关键词）
   ↓
只加载前 N 条（默认 5 条）
   ↓
注入到执行器的上下文
```

**成本控制**：5 条经验约 500 token，换来避免重复踩坑。

## 3. L2：经验固化

### 3.1 什么情况下固化成技能

```
同类任务做了 3 次以上
   ↓
流程基本固定
   ↓
抽取成技能（SKILL.md）
   ↓
下次直接调用，不用重新推理
```

### 3.2 技能的好处

| 好处 | 说明 |
|---|---|
| 省 token | 不用每次重新推理流程 |
| 更稳定 | 固定流程比临场发挥可靠 |
| 可审查 | 你可以看技能内容 |

### 3.3 固化的判断标准

| 该固化 | 不该固化 |
|---|---|
| 步骤固定、重复出现 | 一次性任务 |
| 有明确的成功标准 | 结果主观 |
| 容易出错的环节 | 很简单的操作 |
| 需要多步协调 | 单步操作 |

## 4. L3：代码自我优化

### 4.1 扫描什么

| 类型 | 检测方法 |
|---|---|
| **重复代码** | 相似度分析，找 3 行以上完全相同的块 |
| **死代码** | 没有被任何地方引用的函数/变量 |
| **过长函数** | 超过阈值（如 100 行） |
| **复杂条件** | 嵌套超过 4 层 |
| **未使用依赖** | package.json 里有但代码没用到 |

### 4.2 改动方式（重要）

```
发现可优化项
   ↓
生成改动建议
   ↓
⦿ 走 PR 流程（默认）
   · 创建分支
   · 提交改动
   · 开 PR
   · 等你看
   ↓
○ 直接改（需显式开启）
```

**为什么默认走 PR**：自我修改是高风险操作。你可能不同意它的判断，PR 让你有机会拦下来。

### 4.3 自我修改的红线

**以下内容不允许自动修改**：

| 红线 | 原因 |
|---|---|
| 权限判定逻辑 | 改坏了等于开后门 |
| 白名单检查 | 同上 |
| 审计日志 | 改坏了查不到问题 |
| 熔断/限流 | 改坏了会失控 |
| 配置文件 | 由你控制 |

**这些位置即使发现「可优化」，也只提建议，不改。**

## 5. L4：能力扩展

### 5.1 三种扩展

| 扩展 | 触发条件 | 授权要求 |
|---|---|---|
| **装插件** | 发现缺某个能力 | 权限页勾选 |
| **写技能** | 发现某流程常用 | 权限页勾选 |
| **学知识** | 发现缺某领域知识 | 只需记录，不需授权 |

### 5.2 装插件的流程

```
发现缺能力
   ↓
搜索可用插件（npm / GitHub）
   ↓
⚠ 安全检查：
   · 来源是否可信
   · 是否有已知漏洞
   · 权限范围是否过大
   ↓
生成建议：「需要装 X，理由是 Y，风险是 Z」
   ↓
⦿ 等你确认（默认）
○ 直接装（需显式开启）
```

**为什么默认等确认**：装插件等于引入第三方代码，风险不可控。

### 5.3 能力缺口记录

即使不能自己装，它也会**记录下来**：

```json
{
  "gap": "缺少 PDF 解析能力",
  "encounteredAt": "2026-11-10",
  "timesNeeded": 3,
  "suggestedSolution": "安装 pdf-parse 或类似库",
  "status": "pending-user-decision"
}
```

**积累到一定次数（默认 3 次）才提建议**，避免为一次性需求装东西。

## 6. 进化的边界

### 6.1 能进化的

| 项 | 范围 |
|---|---|
| 经验库 | 无限增长（定期归档） |
| 技能 | 可新增、可修改 |
| 自己的代码 | 走 PR，只改非红线部分 |
| 插件 | 需授权 |

### 6.2 不能进化的

| 项 | 原因 |
|---|---|
| 权限判定逻辑 | 安全红线 |
| 白名单 | 由你控制 |
| 授权凭证 | 由你控制 |
| 熔断阈值 | 防止自己关掉保护 |
| 审计记录 | 不可篡改 |

### 6.3 进化的刹车

```
发现自我修改频率过高
   ↓ 比如一周内提了 10 个自我优化 PR
暂停自我优化
   ↓
提示：「近期自我修改较多，建议先稳定一段时间」
```

**为什么要刹车**：频繁自我修改会让系统变得不可预测。

## 7. 经验库结构

```
<stateDir>/
  lessons/
    2026-11/
      lesson-001.json
      lesson-002.json
      ...
    index.json          ← 索引，按 taskType 分组
    archived/           ← 归档（超过 90 天且未被引用）
```

**index.json**：

```json
{
  "byTaskType": {
    "code-modification": ["lesson-001", "lesson-005"],
    "bug-investigation": ["lesson-002"],
    "documentation": ["lesson-003"]
  },
  "byKeyword": {
    "git-branch": ["lesson-001"],
    "testing": ["lesson-001", "lesson-004"]
  }
}
```

## 8. 效果衡量

怎么知道它真的在变好？

| 指标 | 怎么看 |
|---|---|
| 同类任务耗时 | 应该逐渐下降 |
| 返工率 | 应该逐渐下降 |
| 用户纠正次数 | 应该逐渐下降 |
| 一次通过率 | 应该逐渐上升 |
| 平均 token 消耗 | 应该逐渐下降（因为复用经验） |

**面板上应该有这些数字的趋势图。**

## 9. 配置项

见 [设置界面 · 分组 7：自我进化](04-settings.md#分组-7自我进化)。

关键开关：

| 开关 | 默认 | 说明 |
|---|---|---|
| 自我复盘 | 开 | 每次任务后回顾 |
| 记录经验 | 开 | 写入经验库 |
| 代码扫描 | 开 | 找冗余 |
| 改动方式 | **走 PR** | 不直接改 |
| 自主装插件 | **关** | 需显式开启 |
| 自主写技能 | **关** | 需显式开启 |
| 缺能力时提建议 | 开 | 只建议不动手 |
