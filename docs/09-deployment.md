## 2. 两种安装形态

### 2.1 融合版

**装进你现有的 DSH，多一个入口，不动其它插件。**

```sh
# 1. 创建独立 profile（不覆盖现有）
dsh superagent --from-default-profile web --dump-config > /dev/null

# 2. 安装插件包
dsh plugin --profile superagent add link:<项目路径>

# 3. 配置
# 编辑 ~/.dsh/profiles/superagent/cordis.patch.yml
# 设置 stateDir 和端口

# 4. 启动
dsh --profile superagent
```

**关键**：必须开启「隔离进程环境变量」，否则会影响其它插件的 `gh` / CLI 调用。

### 2.2 纯净版

**全新白板 DSH，只装这个，走官方更新路径。**

```sh
# 1. 用官方方式安装 DSH（如果还没有）
npm install -g @deepseek-ai/dsh

# 2. 创建白板 profile
dsh superagent --from-default-profile web --dump-config > /dev/null

# 3. 安装
dsh plugin --profile superagent add link:<项目路径>

# 4. 启动
dsh --profile superagent
```

**优点**：干净，无历史包袱，可随官方版本升级。

## 3. 配置

### 3.1 最小配置

```yaml
# ~/.dsh/profiles/superagent/cordis.patch.yml
- id: webserver
  config:
    host: 127.0.0.1
    port: 3082

- id: superagent
  config:
    stateDir: <绝对路径>/state/superagent
```

**注意**：`stateDir` 必须是绝对路径。Windows 下用 `C:/path/with/forward/slash` 格式。

### 3.2 完整配置

推荐在界面上配置，不要手改文件。

见 [设置界面](04-settings.md) 的八个分组。

## 4. 首次启动

```
1. 启动进程
   ↓
2. 打开面板（终端会打印带 token 的地址）
   ↓
3. 首次向导开始：
   · 配置 GitHub（仓库 + CLI）
   · 配置其它来源（按需）
   · 配置代理（如需要）
   · 设置权限白名单
   · 设置预算
   ↓
4. 用「观察模式」跑一周
   ↓
5. 看它记录的决定，觉得准了再切「自动模式」
```

## 5. 每种来源需要你提供什么

| 来源 | 需要 | 怎么获取 |
|---|---|---|
| **GitHub** | 仓库 + CLI 授权 | 已登录即可 |
| **企业微信** | 企业 ID + 应用 Secret + AgentId | 企业管理员后台建应用 |
| **QQ邮箱** | 授权码 | 邮箱设置 → 账户 → 开启 IMAP → 生成授权码 |
| **飞书** | App ID + App Secret | 开放平台建自建应用 |
| **Gmail** | 应用专用密码 | 开启两步验证 → 生成应用密码 |
| **QQ** | 已有桥接 | 无需额外配置 |
| **微信** | 本地客户端授权 | 首次扫码登录 |

## 6. 工程量估算

### 6.1 分阶段

| 阶段 | 内容 | 天数 |
|---|---|---|
| **P0** | 修 GitHub 来源 + 环境隔离开关 | 0.5 |
| **P1** | 设置界面骨架（八分组） | 3 |
| **P2** | 模型授权 + 分档 + 省流 | 2 |
| **P3** | 多会话协同（互通/任务板/救援/回测） | 4 |
| **P4** | 代理系统（三层 + 拖拽识别） | 3 |
| **P5** | 自我进化机制 | 2 |
| **P6** | 七个连接源 | 6 |
| **P7** | 稳定性加固（五层） | 2 |
| **P8** | 浏览器授权向导 | 2 |
| **P9** | 双状态 + 前后台切换 | 1.5 |
| **P10** | 打包 + 三语文档 | 2.5 |
| **合计** | | **~28.5 天** |

### 6.2 建议分批

**第一批（3.5 天）**：P0 + P1 + P2
→ 能看见完整的设置界面，能配模型

**第二批（7 天）**：P3 + P4
→ 多会话协同和代理能跑

**第三批（10 天）**：P5 + P6 + P7
→ 自我进化、七源接入、稳定性

**第四批（5.5 天）**：P8 + P9 + P10
→ 浏览器向导、双状态、打包

**为什么不一次做完**：中间需要你验收和调整方向，一次做完容易跑偏。

## 9. 升级

### 9.1 融合版升级

```sh
# 插件升级
dsh plugin --profile superagent update

# DSH 本体升级（跟随你的主版本）
# 注意：主版本大升级可能影响兼容性
```

### 9.2 纯净版升级

```sh
# 完全跟随官方
npm update -g @deepseek-ai/dsh
```

### 9.3 升级前的检查清单

| # | 检查 |
|---|---|
| 1 | 备份 `<stateDir>` |
| 2 | 记录当前配置（导出） |
| 3 | 确认没有正在跑的任务 |
| 4 | 如果是本地补丁版本，确认补丁能重新应用 |

## 10. 故障排查

### 10.1 启动失败

| 症状 | 原因 | 解决 |
|---|---|---|
| `EADDRINUSE` | 端口被占 | 杀掉旧进程或换端口 |
| `ValidationError: stateDir` | 路径格式不对 | 用绝对路径 + 正斜杠 |
| `cannot resolve profile bundle` | 包名不对 | 检查 `package.json` 里的包名 |
| `spawn env ENOENT` | 平台不兼容 | 见下节 |

### 10.2 来源不工作

| 症状 | 检查 |
|---|---|
| 状态 `error` | 看具体错误信息 |
| 状态 `paused` | 配置未完成 |
| 收到 0 条 | 白名单/接收范围没配对 |
| 连续轮询失败 | CLI 路径或授权问题 |

**关键**：看**业务层的状态**，不是只看 `runtime: ready`。

### 10.3 平台兼容性

在某些平台上，原版实现可能需要小幅调整：

| 问题 | 表现 | 处理方向 |
|---|---|---|
| 无 `env` 命令 | `spawn env ENOENT` | 改用进程参数传环境 |
| 路径格式 | `stateDir` 校验失败 | 用平台对应格式 |
| 命令名不同 | 工具注册失败 | 按平台选对应的 shell |
| 端口自我抢占 | 重启时 `EADDRINUSE` | 先停旧进程再起 |

## 11. 安全建议

| # | 建议 | 原因 |
|---|---|---|
| 1 | **独立账号** | 智能体用专用账号，不和你混用 |
| 2 | **最小权限** | 白名单只放必要的人 |
| 3 | **观察模式起步** | 先看它想干什么 |
| 4 | **预算上限** | 防止意外烧钱 |
| 5 | **危险操作二次确认** | 删文件、推送、发消息 |
| 6 | **不开自主装插件** | 除非你信任 |
| 7 | **定期看审计记录** | 知道它做了什么 |

## 12. 最小可用配置

如果你想先跑起来看看，这是最简配置：

```yaml
来源：只开 GitHub
模式：观察（observe）
预算：日 ¥10
自主权限：全关
```

**跑一周，看它记录的决定。** 觉得准了，再逐步放开。
