### 3 つのポリシーの比較

| ポリシー | 長所 | 短所 | 適用 |
|---|---|---|---|
| **統一モデル** | 安価で予測しやすい | 難問では効果が落ちます | タスクが同質な場合 |
| **段階モデル** | 必要な分だけ課金 | 段階の設定が必要です | ほとんどの場面 |
| **マルチモデル並列** | 最も効果が高い | 最も高価です | 重要なタスク |

### 思考深度の役割

思考深度はトークン消費と推論品質に直接影響します：

| 段階 | 相対コスト | 適用 |
|---|---|---|
| 極低 | 1x | 難易度予測、分類 |
| 低 | 2x | 単純な書き換え、整形 |
| 中 | 4x | 通常のコーディング |
| 高 | 8x | 複雑なロジック、アーキテクチャ設計 |
| 最高 | 16x | 極めて難しい推論、自己進化 |

**難易度予測に「極低」を使うのがコスト管理の要です**：50 トークンの判断が、数百トークンの無駄な作業を防ぎます。

### 「実行位置」が重要な理由

| モード | 体験 | 適用 |
|---|---|---|
| **フォアグラウンド** | 一歩ずつ作業を見られます | 学びたいとき、または不安なとき |
| **バックグラウンド** | 邪魔をせず、完了後に通知します | 日常 |
| **タスク次第** | 単純なものは黙って、複雑なものは確認します | バランス |

**このオプションはあなたのためであり、それ自体のためではありません。** いつでも変更できます。

### 3 つの実行状態の違い

| 状態 | プロセス | 画面 | 演算資源（アイドル時） |
|---|---|---|---|
| 対話モード | 必要時に起動 | あり | 0 |
| サイレントモード | 常駐 | なし | ほぼ 0（イベント待ち） |
| デュアルモード | 常駐 | あり | ほぼ 0（イベント待ち） |

### 統一連絡先センターの説明

公式の設計では、ソースをまたぐ身元マッピングを**意図的に行っていません**。本プロジェクトがこの層を追加するのは、「同一人物はどこでもホワイトリストとして扱う」が必須要件だからです。

```json
{
  "uid": "owner",
  "identities": {
    "github": ["<アカウント>"],
    "email": ["<アドレス>"],
    "qq": ["<番号>"],
    "wecom": ["<アカウント>"],
    "feishu": ["<open_id>"]
  },
  "policy": {
    "canRequest": true,
    "canProactive": false
  }
}
```

### 自律権限を項目ごとに分ける理由

**「自律を許可する」は二択ではなく、十数個の二択です。**

| 権限 | リスク |
|---|---|
| 推測依頼を自律的に受ける | 望まないことをする可能性があります |
| プラグインを自律導入 | 信頼できないコードを入れる可能性があります |
| 自分のコードを自律変更 | 壊す可能性があります |
| メッセージを自律送信 | 失言する可能性があります |
| ファイルを自律削除 | 取り返しがつきません |

**推奨**：まずすべてオフにし、1 週間観察してから項目ごとにオンにします。

### 「プロセス環境変数の隔離」が重要な理由

このプラグインはプロセスの `PATH` を変更し、`gh` と `lark-cli` のラッパースクリプトを先頭に挿入します。

**融合版では、これが同一プロセス上の他のプラグインに影響します**。隔離スイッチを有効にすると、内部でのみ独自の環境を使い、グローバルを汚染しません。

**融合版ではこの項目を必ず有効にしてください。**
