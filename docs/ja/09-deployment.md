| 項目 | 要件 |

| DeepSeek Harness | 0.2.x 以上 |

| パッケージマネージャ | pnpm |

## 2. 2 つのインストール形態

### 2.1 融合版

**既存の DSH に組み込み、入り口を 1 つ増やす。他のプラグインには手を付けません。**

```sh
# 1. 独立した profile を作成（既存を上書きしない）
dsh superagent --from-default-profile web --dump-config > /dev/null

# 2. プラグインパッケージをインストール
dsh plugin --profile superagent add link:<プロジェクトパス>

# 3. 設定
# ~/.dsh/profiles/superagent/cordis.patch.yml を編集
# stateDir とポートを設定

# 4. 起動
dsh --profile superagent
```

**重要**：必ず「分離プロセス環境変数」を有効にしてください。そうしないと他のプラグインの `gh` / CLI 呼び出しに影響します。

### 2.2 クリーン版

**まっさらな DSH にこれだけを入れ、公式の更新経路に乗ります。**

```sh
# 1. 公式の方法で DSH をインストール（まだ無い場合）
npm install -g @deepseek-ai/dsh

# 2. まっさらな profile を作成
dsh superagent --from-default-profile web --dump-config > /dev/null

# 3. インストール
dsh plugin --profile superagent add link:<プロジェクトパス>

# 4. 起動
dsh --profile superagent
```

**利点**：クリーンで過去の負債がなく、公式バージョンに追随してアップグレードできます。

## 3. 設定

### 3.1 最小構成

```yaml
# ~/.dsh/profiles/superagent/cordis.patch.yml
- id: webserver
  config:
    host: 127.0.0.1
    port: 3082

- id: superagent
  config:
    stateDir: <絶対パス>/state/superagent
```

**注意**：`stateDir` は絶対パスである必要があります。Windows では `C:/path/with/forward/slash` の形式を使ってください。

### 3.2 完全な設定

画面から設定することを推奨します。ファイルを手で編集しないでください。

[設定画面](04-settings.md) の 8 つのグループを参照してください。

## 4. 初回起動

```
1. プロセスを起動
   ↓
2. パネルを開く（ターミナルに token 付きのアドレスが表示されます）
   ↓
3. 初回ウィザードが開始：
   · GitHub の設定（リポジトリ + CLI）
   · その他のソースの設定（必要に応じて）
   · プロキシの設定（必要なら）
   · 権限ホワイトリストの設定
   · 予算の設定
   ↓
4. 「観察モード」で 1 週間動かす
   ↓
5. 記録された決定を見て、的確だと判断できたら「自動モード」に切り替え
```

## 5. 各ソースで用意が必要なもの

| ソース | 必要 | 取得方法 |
|---|---|---|
| **GitHub** | リポジトリ + CLI 委任 | すでにログイン済みならそのまま |
| **企業微信** | 企業 ID + アプリ Secret + AgentId | 企業管理者コンソールでアプリを作成 |
| **QQ メール** | 認可コード | メール設定 → アカウント → IMAP を有効化 → 認可コードを生成 |
| **飛書** | App ID + App Secret | オープンプラットフォームで自社アプリを作成 |
| **Gmail** | アプリ専用パスワード | 2 段階認証を有効化 → アプリパスワードを生成 |
| **QQ** | 既存のブリッジ | 追加設定は不要 |
| **WeChat** | ローカルクライアントの委任 | 初回に QR コードでログイン |

## 6. 工数の見積もり

### 6.1 フェーズ別

| フェーズ | 内容 | 日数 |
|---|---|---|
| **P0** | GitHub ソースの修正 + 環境分離スイッチ | 0.5 |
| **P1** | 設定画面の骨格（8 グループ） | 3 |
| **P2** | モデル委任 + 段階分け + コスト管理 | 2 |
| **P3** | マルチセッション協調（相互通信 / タスクボード / レスキュー / バックテスト） | 4 |
| **P4** | プロキシシステム（3 層 + ドラッグ認識） | 3 |
| **P5** | 自己進化の仕組み | 2 |
| **P6** | 7 つの接続ソース | 6 |
| **P7** | 安定性の強化（5 層） | 2 |
| **P8** | ブラウザ委任ウィザード | 2 |
| **P9** | 二重状態 + 前面/背面の切り替え | 1.5 |
| **P10** | パッケージング + 3 言語ドキュメント | 2.5 |
| **合計** | | **~28.5 日** |

### 6.2 バッチ分割の推奨

**第 1 バッチ（3.5 日）**：P0 + P1 + P2
→ 設定画面の全体が見え、モデルも設定できる

**第 2 バッチ（7 日）**：P3 + P4
→ マルチセッション協調とプロキシが動く

**第 3 バッチ（10 日）**：P5 + P6 + P7
→ 自己進化、7 ソース接続、安定性

**第 4 バッチ（5.5 日）**：P8 + P9 + P10
→ ブラウザウィザード、二重状態、パッケージング

**なぜ一度に完成させないのか**：途中であなたの受け入れ確認と方向修正が必要です。一度に作り切ると逸脱しやすくなります。

## 8. データの保存場所

```
<stateDir>/
  orchestrator.sqlite    ← メインデータベース
  worker-bin/            ← コマンドシム
  work/                  ← チケットの作業ディレクトリ
  lessons/               ← 経験ライブラリ
  logs/                  ← ログ
  config-backup/         ← 設定バックアップ
```

**バックアップ方針**：`<stateDir>` ディレクトリ全体を定期的にバックアップすれば十分です。

## 9. アップグレード

### 9.1 融合版のアップグレード

```sh
# プラグインのアップグレード
dsh plugin --profile superagent update

# DSH 本体のアップグレード（メジャーバージョンに追随）
# 注意：メジャーバージョンの大幅アップグレードは互換性に影響する場合があります
```

### 9.2 クリーン版のアップグレード

```sh
# 完全に公式に追随
npm update -g @deepseek-ai/dsh
```

### 9.3 アップグレード前のチェックリスト

| # | 確認項目 |
|---|---|
| 1 | `<stateDir>` をバックアップ |
| 2 | 現在の設定を記録（エクスポート） |
| 3 | 実行中のタスクがないことを確認 |
| 4 | ローカルパッチ版の場合、パッチを再適用できることを確認 |

## 10. トラブルシューティング

### 10.1 起動失敗

| 症状 | 原因 | 対処 |
|---|---|---|
| `EADDRINUSE` | ポートが使用中 | 古いプロセスを終了するか、ポートを変更 |
| `ValidationError: stateDir` | パスの形式が不正 | 絶対パス + スラッシュ（/）を使う |
| `cannot resolve profile bundle` | パッケージ名が不正 | `package.json` のパッケージ名を確認 |
| `spawn env ENOENT` | プラットフォーム非互換 | 次節を参照 |

### 10.2 ソースが動かない

| 症状 | 確認項目 |
|---|---|
| 状態が `error` | 具体的なエラーメッセージを見る |
| 状態が `paused` | 設定が未完了 |
| 0 件しか受信しない | ホワイトリスト/受信範囲が合っていない |
| ポーリングが連続で失敗 | CLI のパスまたは委任の問題 |

**重要**：`runtime: ready` だけを見るのではなく、**業務レイヤーの状態**を見てください。

### 10.3 プラットフォーム互換性

一部のプラットフォームでは、元の実装に小さな調整が必要になる場合があります：

| 問題 | 症状 | 対処の方向性 |
|---|---|---|
| `env` コマンドが無い | `spawn env ENOENT` | プロセス引数で環境を渡す方式に変更 |
| パスの形式 | `stateDir` の検証失敗 | プラットフォームに合った形式を使う |
| コマンド名が異なる | ツール登録の失敗 | プラットフォームに合った shell を選ぶ |
| ポートの自己占有 | 再起動時に `EADDRINUSE` | 先に古いプロセスを止めてから起動 |

## 11. セキュリティ推奨事項

| # | 推奨 | 理由 |
|---|---|---|
| 1 | **専用アカウント** | エージェントは専用アカウントを使い、あなたと共用しない |
| 2 | **最小権限** | ホワイトリストには必要な人だけを入れる |
| 3 | **観察モードから開始** | まず何をしようとするかを見る |
| 4 | **予算上限** | 事故による出費を防ぐ |
| 5 | **危険な操作は二段階確認** | ファイル削除、プッシュ、メッセージ送信 |
| 6 | **プラグインの自律導入はオフ** | 信頼できると判断した場合のみ |
| 7 | **監査記録を定期的に見る** | 何をしたかを把握する |

---

## 12. 最小構成で動かす

まず動かして眺めたい場合、これが最も簡素な設定です：

```yaml
ソース：GitHub のみ有効
モード：観察（observe）
予算：日次 ¥10
自律権限：すべてオフ
```

**1 週間動かして、記録された決定を見てください。** 的確だと判断できたら、少しずつ開放していきます。
