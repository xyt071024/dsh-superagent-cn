3 つのポリシーの比較

ポリシー長所短所適用
統一モデル安価で予測しやすい難問では効果が落ちますタスクが同質な場合
段階モデル必要な分だけ課金段階の設定が必要ですほとんどの場面
マルチモデル並列最も効果が高い最も高価です重要なタスク

思考深度の役割

思考深度はトークン消費と推論品質に直接影響します：

段階相対コスト適用
極低1x難易度予測、分類
低2x単純な書き換え、整形
中4x通常のコーディング
高8x複雑なロジック、アーキテクチャ設計
最高16x極めて難しい推論、自己進化

難易度予測に「極低」を使うのがコスト管理の要です：50 トークンの判断が、数百トークンの無駄な作業を防ぎます。

「実行位置」が重要な理由

モード体験適用
フォアグラウンド一歩ずつ作業を見られます学びたいとき、または不安なとき
バックグラウンド邪魔をせず、完了後に通知します日常
タスク次第単純なものは黙って、複雑なものは確認しますバランス

このオプションはあなたのためであり、それ自体のためではありません。 いつでも変更できます。

統一連絡先センターの説明

公式の設計では、ソースをまたぐ身元マッピングを意図的に行っていません。本プロジェクトがこの層を追加するのは、「同一人物はどこでもホワイトリストとして扱う」が必須要件だからです。

{
  "uid": "owner",
  "identities": {
    "github": ["<アカウント>"],
    "email": ["<アドレス>"],
    "qq": ["<番号>"],
    "wecom": ["<アカウント>"],
    "feishu": ["<open_id>"]
  },
  "policy": {
    "canRequest": true,
    "canProactive": false
  }
}

自律権限を項目ごとに分ける理由

「自律を許可する」は二択ではなく、十数個の二択です。

権限リスク
推測依頼を自律的に受ける望まないことをする可能性があります
プラグインを自律導入信頼できないコードを入れる可能性があります
自分のコードを自律変更壊す可能性があります
メッセージを自律送信失言する可能性があります
ファイルを自律削除取り返しがつきません

推奨：まずすべてオフにし、1 週間観察してから項目ごとにオンにします。

「プロセス環境変数の隔離」が重要な理由

このプラグインはプロセスの PATH を変更し、gh と lark-cli のラッパースクリプトを先頭に挿入します。

融合版では、これが同一プロセス上の他のプラグインに影響します。隔離スイッチを有効にすると、内部でのみ独自の環境を使い、グローバルを汚染しません。

融合版ではこの項目を必ず有効にしてください。
