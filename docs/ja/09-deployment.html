項目要件

パッケージマネージャpnpm
OSWindows 10/11、macOS、Linux

2. 2 つのインストール形態

2.1 融合版

既存の DSH に組み込み、入り口を 1 つ増やす。他のプラグインには手を付けません。

# 1. 独立した profile を作成（既存を上書きしない）
dsh superagent --from-default-profile web --dump-config > /dev/null

# 2. プラグインパッケージをインストール
dsh plugin --profile superagent add link:<プロジェクトパス>

# 3. 設定
# ~/.dsh/profiles/superagent/cordis.patch.yml を編集
# stateDir とポートを設定

# 4. 起動
dsh --profile superagent

重要：必ず「分離プロセス環境変数」を有効にしてください。そうしないと他のプラグインの gh / CLI 呼び出しに影響します。

2.2 クリーン版

まっさらな DSH にこれだけを入れ、公式の更新経路に乗ります。

# 1. 公式の方法で DSH をインストール（まだ無い場合）
npm install -g @deepseek-ai/dsh

# 2. まっさらな profile を作成
dsh superagent --from-default-profile web --dump-config > /dev/null

# 3. インストール
dsh plugin --profile superagent add link:<プロジェクトパス>

# 4. 起動
dsh --profile superagent

利点：クリーンで過去の負債がなく、公式バージョンに追随してアップグレードできます。

3. 設定

3.1 最小構成

# ~/.dsh/profiles/superagent/cordis.patch.yml
- id: webserver
  config:
    host: 127.0.0.1
    port: 3082

- id: superagent
  config:
    stateDir: <絶対パス>/state/superagent

注意：stateDir は絶対パスである必要があります。Windows では C:/path/with/forward/slash の形式を使ってください。

3.2 完全な設定

画面から設定することを推奨します。ファイルを手で編集しないでください。

設定画面 の 8 つのグループを参照してください。

4. 初回起動

1. プロセスを起動
   ↓
2. パネルを開く（ターミナルに token 付きのアドレスが表示されます）
   ↓
3. 初回ウィザードが開始：
   · GitHub の設定（リポジトリ + CLI）
   · その他のソースの設定（必要に応じて）
   · プロキシの設定（必要なら）
   · 権限ホワイトリストの設定
   · 予算の設定
   ↓
4. 「観察モード」で 1 週間動かす
   ↓
5. 記録された決定を見て、的確だと判断できたら「自動モード」に切り替え

8. データの保存場所

<stateDir>/
  orchestrator.sqlite    ← メインデータベース
  worker-bin/            ← コマンドシム
  work/                  ← チケットの作業ディレクトリ
  lessons/               ← 経験ライブラリ
  logs/                  ← ログ
  config-backup/         ← 設定バックアップ

バックアップ方針：<stateDir> ディレクトリ全体を定期的にバックアップすれば十分です。

9. アップグレード

9.1 融合版のアップグレード

# プラグインのアップグレード
dsh plugin --profile superagent update

# DSH 本体のアップグレード（メジャーバージョンに追随）
# 注意：メジャーバージョンの大幅アップグレードは互換性に影響する場合があります

9.2 クリーン版のアップグレード

# 完全に公式に追随
npm update -g @deepseek-ai/dsh

9.3 アップグレード前のチェックリスト

#確認項目
1<stateDir> をバックアップ
2現在の設定を記録（エクスポート）
3実行中のタスクがないことを確認
4ローカルパッチ版の場合、パッチを再適用できることを確認

10. トラブルシューティング

10.1 起動失敗

症状原因対処
EADDRINUSEポートが使用中古いプロセスを終了するか、ポートを変更
ValidationError: stateDirパスの形式が不正絶対パス + スラッシュ（/）を使う
cannot resolve profile bundleパッケージ名が不正package.json のパッケージ名を確認
spawn env ENOENTプラットフォーム非互換次節を参照

10.2 ソースが動かない

症状確認項目
状態が error具体的なエラーメッセージを見る
状態が paused設定が未完了
0 件しか受信しないホワイトリスト/受信範囲が合っていない
ポーリングが連続で失敗CLI のパスまたは委任の問題

重要：runtime: ready だけを見るのではなく、業務レイヤーの状態を見てください。

10.3 プラットフォーム互換性

一部のプラットフォームでは、元の実装に小さな調整が必要になる場合があります：

問題症状対処の方向性
env コマンドが無いspawn env ENOENTプロセス引数で環境を渡す方式に変更
パスの形式stateDir の検証失敗プラットフォームに合った形式を使う
コマンド名が異なるツール登録の失敗プラットフォームに合った shell を選ぶ
ポートの自己占有再起動時に EADDRINUSE先に古いプロセスを止めてから起動

11. セキュリティ推奨事項

#推奨理由
1専用アカウントエージェントは専用アカウントを使い、あなたと共用しない
2最小権限ホワイトリストには必要な人だけを入れる
3観察モードから開始まず何をしようとするかを見る
4予算上限事故による出費を防ぐ
5危険な操作は二段階確認ファイル削除、プッシュ、メッセージ送信
6プラグインの自律導入はオフ信頼できると判断した場合のみ
7監査記録を定期的に見る何をしたかを把握する

12. 最小構成で動かす

まず動かして眺めたい場合、これが最も簡素な設定です：

ソース：GitHub のみ有効
モード：観察（observe）
予算：日次 ¥10
自律権限：すべてオフ

1 週間動かして、記録された決定を見てください。 的確だと判断できたら、少しずつ開放していきます。
