完整任务流程

本文按时间顺序完整还原：一条消息从进来到回信，每一步发生了什么，用什么接口。

1. 阶段 0：进程启动

步骤动作位置
1读配置文件~/.dsh/profiles/<name>/cordis.patch.yml
2打开数据库 + 加文件锁<stateDir>/orchestrator.sqlite
3探测账号（gh api user 等）部署检查
4写 worker 命令垫片目录<stateDir>/worker-bin
5创建主会话使用专用预设
6启动调度循环每 2 秒一次

注意：调度是轮询（每 2 秒扫一次），不是事件驱动。这是官方实现，后续的「静默态」改造会替换这一层。

2. 阶段 1：消息进入（被动路径）

2.1 时序

[1] 平台有新消息
      ↓ 轮询（默认 60 秒一次）
[2] Source 拉取
      ↓
[3] 翻译成 Trigger
      ↓ 记录：发件人、正文、线程标识、是否提及
[4] 入库 + 去重
      ↓ 同一 Trigger 只存一次
[5] 判断归属
      ├─ 新线程 → 建线程，排入评估队列
      └─ 已有线程 → 扇出给订阅的工单（作为上下文，不授权）
[6] 调度循环扫到
      ↓
[7] 组装候选卡片
      ↓
[8] 推入主会话

2.2 关键接口

动作接口
拉消息平台各自的 API / CLI
存 TriggerEngine.receive(trigger)
看候选上下文orchestrator_eval
读更多上下文orchestrator_eval_read
记录决定orchestrator_eval_decide
路由决定orchestrator_route

3. 阶段 2：网关（纯代码）

Trigger 进来
   ↓
gate(trigger, thread, tickets)     ← 纯函数，无模型
   ↓
步骤：
   ① 查发件人是否在白名单
   ② 查是否机器人账号
   ③ 查准入表的对应格子
   ↓
输出三选一：
   explicit   —— 明确请求
   inferred   —— 推断候选
   not admitted —— 丢弃

这一步不看消息内容。 这是权限防线的基石。

3.1 准入表

每个来源都有一张准入表，行是「接收范围」，列是三种情况：

格子选项默认
在名单但没点名推断 / 忽略推断
不在名单但点名了明确 / 推断 / 忽略忽略
不在名单也没点名推断 / 忽略忽略

示例：如果把「不在名单但点名了」设为「明确」，就等于「任何人在这个范围里 @ 它都能派活」——适合专门的客服群。

4. 阶段 3：评估（模型）

4.1 三个必须成立的事实

事实判断标准
① 讨论针对本项目不是聊别家产品、不是假设性假设
② 有实现意图明确表达了要实现某个具体改动
③ 方向已确定能直接做小范围局部修改，不是还在争论设计

三个都成立才接单。 缺任一条就忽略。

4.2 输出结构

{
  "rule_assessments": [
    { "rule_id": "copy",   "matched": true,  "reason": "明确要求改文案" },
    { "rule_id": "visual", "matched": false, "reason": "不涉及视觉调整" }
  ],
  "direction": {
    "implementation_requested": true,
    "target_basis": "existing-standard",
    "requires_design_decision": false,
    "evidence": ["原文引用"]
  },
  "acknowledgement": "一句话说明要做什么"
}

注意：rule_assessments 必须对每个启用的规则都给一条，无论命中与否。漏了会报错。

4.3 上下文窗口

评估时能看到的：

内容长度
触发文本最多 4000 字符
线程前 5 条消息各限 400 字符
触发前后各 5 条相邻两条可到 1200 字符
关联工单最多 8 个，进行中的优先
其他消息50 字符摘要，可按 id 展开

5. 阶段 4：接单

orchestrator_route {kind: "accept", ...}
   ↓
单事务内完成：
   ├─ 建 Decision
   ├─ 建 Ticket
   ├─ 建 Mandate（记策略版本 / 范围 / 强度 / 命中规则）
   ├─ 建 Assignment（待启动）
   ├─ 建 Subscription（订阅所有相关线程）
   └─ 排队发确认消息
   ↓
进入执行队列

幂等性：同一个 Trigger ID 重复接单只会建一个工单。

6. 阶段 5：执行

6.1 启动执行器

[1] 跑 prepare 命令（如配置了）—— 限时 10 分钟
[2] 建目录 <stateDir>/work/<短名>
[3] 起会话，命名 worker-<工单ID>
[4] 发第一条消息：标题 + 任务说明 + 源事件卡片

6.2 执行器的工具集

类别工具
文件read write edit glob grep read_image
命令bash / pwsh job_output job_list job_kill
网络web_search web_fetch
协作subagent send_message list_agents interrupt_agent
其它skill todo_write

6.3 工作流程

1. 读仓库里的 AGENTS.md（项目自带规则）
2. 判断范围：这活在我的授权内吗？
   ├─ 不在 → 交还（handback）
   └─ 在 → 继续
3. 动手前先确认：一句话说清要干什么
4. 干活：改代码 / 跑测试 / 自检
5. 长命令转后台（前台超过 5 秒自动转）
6. 汇报

6.4 六种报告状态

状态含义后果
progress内部进度不通知任何人
waiting这轮干完，没有悬着的问题转空闲，等下条消息
ready干完且自检通过转「等审核」
blocked缺东西，必须人介入转「受阻」
failed失败转「失败」
dropped无需处理关单，不发消息

6.5 后台活的限制

项值
单轮后台活最长时间30 分钟
到期处理杀掉 shell 任务，报告里说明杀了什么
子代理允许继续
交给人时子代理立即停止，shell 任务可继续

7. 阶段 6：回信

7.1 三种路径

路径何时约束
确认接单时 / 开始干之前硬上限 100 词
结果报 ready需工单确实就绪
提问需要人做决定必须逐字复制原问题

7.2 落点规则

工单来自哪个线程 → 回到那里
   例外：如果问题由人提出 → 回到提问者所在的会话

7.3 100 词是硬约束

这不是建议，是传输层拒绝。

原文："100 words is a hard ceiling, not a writing target. The transport rejects longer IM messages."

中文按分词计算，Markdown 链接的标签和地址都计入。

8. 阶段 7：后续消息

8.1 订阅机制

工单接单时会订阅所有相关线程。之后：

  • 线程里任何新消息 → 自动到达工单（作为上下文，不授权）
  • 不需要再 @ 它
  • 机器人消息和 CI 结果也会到达

8.2 工单结束后的续接

工单结束（ready/merged/closed）
   ↓
订阅保留
   ↓
有人在同线程继续说话
   ↓
自动续上（同一授权，不用重新评估）
   ↓
如果授权条件已变 → 重校验失败 → 不续，重新走评估

9. 完整时序示例

场景：GitHub 有人请求改文案

T+0      有人在 Issue 里评论 @它：「这个按钮文字改成 Save」
T+60     轮询周期到，拉到通知
T+60     翻译成 Trigger，入库，建线程，排入评估
T+62     调度循环扫到，组装卡片，推入主会话
T+65     模型判断：
           ① 针对本项目 ✓
           ② 有实现意图 ✓
           ③ 方向确定（具体改成 Save）✓
         命中 copy 规则 → 接单
T+65     建工单 + 授权 + 派工 + 订阅（单事务）
T+66     发确认：「收到：把设置页的『保存更改』按钮改成『保存』」
T+66     启动执行器：建目录 → 起会话 → 发任务
T+72     执行器开始干活
T+80     改完，跑测试，自检
T+95     报 ready
T+96     主会话发结果回原线程
T+97     完成

场景：邮箱来一个复杂需求

T+0      邮箱收到邮件
T+1      IMAP 推送 → 翻译成 Trigger
T+2      网关判断：发件人在白名单 → 明确请求
T+3      主会话先做难度预判（低思考深度，约 50 token）
T+5      判断「复杂」→ 需要拆 3 个子会话
T+6      开子会话 A/B/C，各指定模型
         → 详见 [多会话协同](03-collaboration.md)
...
T+167    最终回测通过，发结果邮件

10. 异常路径

10.1 评估超时

候选到达主会话后开始计时（默认 120 秒）
   ↓ 超时
排队重试
   ↓ 连续两次都超时
第三次记为「未完成」（unavailable）
   ↓
面板提示人工处理

10.2 执行器卡住

情况处理
报 blocked停止自动输入，等人
报 failed同上
无心跳（超时）标记疑似卡死，主会话决定接管/重启
供应商临时故障自动重试 3 次（5 秒起，翻倍到 300 秒）

10.3 来源失败

情况处理
单条读取失败错误记在该线程上，下轮重试
连续失败 N 次来源标记为错误
某条持续失败一天丢弃该条，不再阻塞轮询

10.4 回信失败

情况处理
发送失败5 秒起重试，翻倍到 300 秒
会话已不存在标记为「丢弃」，不重发到别处
来源已关闭等待，不丢弃
