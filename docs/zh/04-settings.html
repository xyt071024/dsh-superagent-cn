三档策略对比

策略优点缺点适用
统一模型便宜、可预测难题效果差任务同质化
分档模型按需付费需要配置档位大多数场景
多模型并行效果最好最贵关键任务

思考深度的作用

思考深度直接影响 token 消耗和推理质量：

档位相对成本适用
极低1x难度预判、分类
低2x简单改写、格式化
中4x常规编码
高8x复杂逻辑、架构设计
最高16x极难推理、自我进化

难度预判用「极低」是省流的关键：50 token 的判断，避免几百 token 的白干。

「执行位置」为什么重要

模式体验适用
前台你能看着它一步步做你想学、或者不放心
后台不打扰你，做完通知日常
由任务决定简单的不打扰，复杂的问你平衡

这个选项是给你的，不是给它的。 你随时可以改。

三种运行状态的差别

状态进程界面算力（空闲时）
对话态按需启动有0
静默态常驻无接近 0（等事件）
双态常驻有接近 0（等事件）

自主权限为什么逐项拆

「允许它自主」不是一个是非题，是十几个是非题。

权限风险
自主接推断请求可能做你不想要的事
自主装插件可能装进不可信代码
自主改自己代码可能改坏
自主发消息可能说错话
自主删文件不可逆

建议：先全关，用一周观察，再逐项开。

「隔离进程环境变量」为什么重要

这个插件会修改进程的 PATH，把 gh 和 lark-cli 的包装脚本插到最前。

融合版下，这会影响同进程的其它插件。开启隔离开关后，它只在内部使用自己的环境，不污染全局。

融合版必须开这一项。
