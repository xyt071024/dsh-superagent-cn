项要求

系统Windows 10/11、macOS、Linux

2. 两种安装形态

2.1 融合版

装进你现有的 DSH，多一个入口，不动其它插件。

# 1. 创建独立 profile（不覆盖现有）
dsh superagent --from-default-profile web --dump-config > /dev/null

# 2. 安装插件包
dsh plugin --profile superagent add link:<项目路径>

# 3. 配置
# 编辑 ~/.dsh/profiles/superagent/cordis.patch.yml
# 设置 stateDir 和端口

# 4. 启动
dsh --profile superagent

关键：必须开启「隔离进程环境变量」，否则会影响其它插件的 gh / CLI 调用。

2.2 纯净版

全新白板 DSH，只装这个，走官方更新路径。

# 1. 用官方方式安装 DSH（如果还没有）
npm install -g @deepseek-ai/dsh

# 2. 创建白板 profile
dsh superagent --from-default-profile web --dump-config > /dev/null

# 3. 安装
dsh plugin --profile superagent add link:<项目路径>

# 4. 启动
dsh --profile superagent

优点：干净，无历史包袱，可随官方版本升级。

3. 配置

3.1 最小配置

# ~/.dsh/profiles/superagent/cordis.patch.yml
- id: webserver
  config:
    host: 127.0.0.1
    port: 3082

- id: superagent
  config:
    stateDir: <绝对路径>/state/superagent

注意：stateDir 必须是绝对路径。Windows 下用 C:/path/with/forward/slash 格式。

8.1 一个实例只服务一件事

如果你有两个仓库、两个团队、或者两个平台账号，开两个实例，不要让一个实例管两件。

一条硬规则：

一个实例 = 一个 profile = 一个仓库 = 一个 bot。

实例之间什么都不共享：profile、状态目录、端口、账号白名单，各自独立。这样改一个不会碰到另一个。

加第二个实例时，最要紧的是别动第一个。 四件事各自唯一：

项规则
profile新名字，不复用
端口换一个，先确认没被占
stateDir新目录，绝对路径（插件不展开 ~）
bot 凭据目录必须独立 —— 共用凭据目录等于两个实例用同一个身份活动

每一步都要显式写 --profile，不要依赖脚本默认值——默认值是给单实例用的。

完整步骤（含只读预检、配置解析校验、按 revision 保存设置、验收清单）见源码仓库的 docs/009-second-instance.md。

最容易漏的两处：

  1. 新 profile 没有配模型。桌面 profile 里能用的模型，新 profile 里可能根本不存在——不同 profile 的 provider 是各自插件注册的。设置里的 eval / executor 模型必须挑新 profile 真有的。
  2. 首次启动 status 退出 3 是正常的，意思是「服务起来了，还在等设置」。这时不要反复重启，去把设置保存完。

9. 升级

9.1 融合版升级

# 插件升级
dsh plugin --profile superagent update

# DSH 本体升级（跟随你的主版本）
# 注意：主版本大升级可能影响兼容性

9.2 纯净版升级

# 完全跟随官方
npm update -g @deepseek-ai/dsh

9.3 升级前的检查清单

#检查
1备份 <stateDir>
2记录当前配置（导出）
3确认没有正在跑的任务
4如果是本地补丁版本，确认补丁能重新应用

10. 故障排查

10.1 启动失败

症状原因解决
EADDRINUSE端口被占杀掉旧进程或换端口
ValidationError: stateDir路径格式不对用绝对路径 + 正斜杠
cannot resolve profile bundle包名不对检查 package.json 里的包名
spawn env ENOENT平台不兼容见下节

10.2 来源不工作

症状检查
状态 error看具体错误信息
状态 paused配置未完成
收到 0 条白名单/接收范围没配对
连续轮询失败CLI 路径或授权问题

关键：看业务层的状态，不是只看 runtime: ready。

10.3 平台兼容性

在某些平台上，原版实现可能需要小幅调整：

问题表现处理方向
无 env 命令spawn env ENOENT改用进程参数传环境
路径格式stateDir 校验失败用平台对应格式
命令名不同工具注册失败按平台选对应的 shell
端口自我抢占重启时 EADDRINUSE先停旧进程再起

11. 安全建议

#建议原因
1独立账号智能体用专用账号，不和你混用
2最小权限白名单只放必要的人
3观察模式起步先看它想干什么
4预算上限防止意外烧钱
5危险操作二次确认删文件、推送、发消息
6不开自主装插件除非你信任
7定期看审计记录知道它做了什么
