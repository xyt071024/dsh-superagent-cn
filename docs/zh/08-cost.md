# 08 · 省流与成本控制

## 1. 为什么需要省流

多会话协同意味着**一个任务可能开 6 个会话**。如果每个都用最强模型、最高思考深度，成本会是单会话的十几倍。

**成本失控的典型场景**：

```
一个「中等」任务
   ↓ 没做难度预判
开了 6 个子会话
   ↓ 全用最强模型
   ↓ 全用最高思考深度
   ↓ 每个会话重复读同样的上下文
总消耗 = 单会话的 20 倍以上
```

**省流的目标不是「少花钱」，是「不花冤枉钱」。**

---

## 2. 三级控制

### L1：任务难度预判（最有效）

```
任务到达
   ↓
用极轻量模型跑一次分类
   · 模型：最便宜的那个
   · 思考深度：极低
   · 输出：一个词
   ↓
约 50 token
   ↓
决定后续策略
```

**50 token 换几百上千 token 的节省，这是性价比最高的一步。**

### L2：按难度分档

| 难度 | 模型档位 | 思考深度 | 子会话数 |
|---|---|---|---|
| **simple** | 便宜模型 | 低 | 0（自己做） |
| **medium** | 标准模型 | 中 | 0-2 |
| **complex** | 强模型 | 高 | 3-4 |
| **extreme** | 强模型 | 最高 | 5-6 |

### L3：运行中降级

```
监控实际消耗
   ↓
超过预算的 80%
   ↓
⚠ 警告 + 后续任务降档
   ↓
超过 100%
   ↓
暂停（等你决定）
```

## 3. 难度预判的实现

### 3.1 提示词

```
判断这个任务的复杂度，只输出一个词：

simple  —— 单文件小改动、简单问答、格式调整
medium  —— 多文件协调、需要理解上下文
complex —— 跨模块重构、需要设计方案
extreme —— 需要架构决策、多系统集成

任务：
{task}
```

### 3.2 为什么用「极低」思考深度

分类任务不需要深度推理。用「极低」：
- 成本约为「最高」的 1/16
- 准确率损失很小（任务描述通常够清晰）

### 3.3 误判的处理

**预判可能出错。** 两种情况：

| 情况 | 处理 |
|---|---|
| 预判「简单」实际很难 | 执行中发现卡住 → 升级重判 |
| 预判「复杂」实际很简单 | 前 2 分钟没进展 → 降级自己做 |

**判断依据**：执行 2 分钟后检查进度，如果「简单」任务毫无进展，重新评估。

## 4. 上下文复用

### 4.1 问题

同一条线程的消息，多个工单都要读。每次重读 = 重复消耗。

### 4.2 解法

```
第一次读某条线程
   ↓
摘要 + 关键片段缓存
   ↓
后续工单读 → 命中缓存
   ↓
只补充新增部分
```

**缓存有效期**：线程有新消息则失效对应部分。

### 4.3 缓存粒度

| 内容 | 缓存策略 |
|---|---|
| 线程完整历史 | 摘要缓存（保留关键事实） |
| 仓库文件 | 按 commit hash 缓存 |
| 模型响应 | KV Cache（同前缀复用） |

---

## 5. 结果缓存

### 5.1 什么能缓存

| 能缓存 | 不能缓存 |
|---|---|
| 代码分析结果 | 涉及实时状态的 |
| 文档摘要 | 依赖当前时间的 |
| 文件结构 | 需要最新数据的 |
| 相似任务的方案 | 用户明确要求重做的 |

### 5.2 缓存键

```
key = hash(任务类型 + 目标文件 + 目标文件的 hash + 关键参数)
```

**文件变了，缓存就失效。**

## 6. 模型分档策略

### 6.1 三种策略对比

| 策略 | 成本 | 效果 | 适用 |
|---|---|---|---|
| **统一模型** | 中等 | 稳定 | 任务同质化 |
| **分档模型** | 最省 | 按需 | 大多数场景 |
| **多模型并行** | 最贵 | 最好 | 关键任务 |

### 6.2 分档配置示例

```
难度预判   → 最便宜模型   极低思考
简单任务   → flash 级     低思考
中等任务   → 标准级       中思考
复杂任务   → 强模型       高思考
极复杂任务 → 最强模型     最高思考
自我进化   → 最强模型     最高思考（频率低，值得）
```

### 6.3 思考深度的成本关系

| 档位 | 相对 token 消耗 |
|---|---|
| 极低 | 1x |
| 低 | 2x |
| 中 | 4x |
| 高 | 8x |
| 最高 | 16x |

**这就是为什么「难度预判用极低」这么重要。**

## 7. 预算控制

### 7.1 三层预算

| 层级 | 超出后 |
|---|---|
| **日预算** | 暂停（可配置为降档） |
| **月预算** | 暂停 + 通知 |
| **单任务预算** | 降档或中止 |

### 7.2 预算提示

面板上实时显示：

```
日预算  ¥50
已用    ¥12.4  ▓▓▓▓▓░░░░░░░░░░░░░  24.8%
今日任务 8 个，平均 ¥1.55/任务
```

### 7.3 超预算的处理

```
接近预算（80%）
   ↓
⚠ 警告：后续任务自动降档

超过预算（100%）
   ↓
⦿ 暂停（默认）：新任务排队，等你决定
○ 降档：继续但只用便宜模型
○ 不限：继续正常执行
```

## 8. 多会话的成本放大

### 8.1 成本模型

```
单会话成本 = C

N 个会话并行：
  理论成本 = N × C
  实际成本 = N × C × 1.3（协调开销）

但节省的时间 = N 倍
```

**所以多会话是「用钱换时间」。**

### 8.2 什么时候值得

| 值得 | 不值得 |
|---|---|
| 任务能真正并行 | 强顺序依赖 |
| 时间敏感 | 不着急 |
| 复杂度高 | 简单任务 |
| 成本可接受 | 预算紧张 |

### 8.3 成本上限保护

```
☑ 单任务成本上限  ¥ [ 10 ]
超出后：暂停并询问
```

**防止一个任务意外烧掉一整天预算。**

## 9. 实测数据参考

以下是**示例数据**，实际因任务和模型而异：

| 场景 | 单会话 | 多会话（4个） | 倍数 |
|---|---|---|---|
| 简单改文案 | ¥0.05 | 不拆 | 1x |
| 中等改功能 | ¥0.8 | ¥2.4（3个） | 3x |
| 复杂重构 | ¥5 | ¥18（5个） | 3.6x |
| 极复杂系统 | ¥20 | ¥60（6个） | 3x |

**注意**：多会话不是 N 倍成本，因为每个会话的任务范围更小，单会话成本更低。

## 11. 反模式

| 反模式 | 问题 |
|---|---|
| 全部用最强模型 | 成本 10 倍，效果提升有限 |
| 全部用最高思考 | 同上 |
| 所有任务都拆多会话 | 协调开销 > 收益 |
| 不做难度预判 | 小任务也走重流程 |
| 不设预算上限 | 一次意外烧光 |
| 每次任务都深度复盘 | 复盘成本 > 任务成本 |
