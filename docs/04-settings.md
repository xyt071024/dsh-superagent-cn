### 三档策略对比

| 策略 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| **统一模型** | 便宜、可预测 | 难题效果差 | 任务同质化 |
| **分档模型** | 按需付费 | 需要配置档位 | 大多数场景 |
| **多模型并行** | 效果最好 | 最贵 | 关键任务 |

### 思考深度的作用

思考深度直接影响 token 消耗和推理质量：

| 档位 | 相对成本 | 适用 |
|---|---|---|
| 极低 | 1x | 难度预判、分类 |
| 低 | 2x | 简单改写、格式化 |
| 中 | 4x | 常规编码 |
| 高 | 8x | 复杂逻辑、架构设计 |
| 最高 | 16x | 极难推理、自我进化 |

**难度预判用「极低」是省流的关键**：50 token 的判断，避免几百 token 的白干。

### 「执行位置」为什么重要

| 模式 | 体验 | 适用 |
|---|---|---|
| **前台** | 你能看着它一步步做 | 你想学、或者不放心 |
| **后台** | 不打扰你，做完通知 | 日常 |
| **由任务决定** | 简单的不打扰，复杂的问你 | 平衡 |

**这个选项是给你的，不是给它的。** 你随时可以改。

### 三种运行状态的差别

| 状态 | 进程 | 界面 | 算力（空闲时） |
|---|---|---|---|
| 对话态 | 按需启动 | 有 | 0 |
| 静默态 | 常驻 | 无 | 接近 0（等事件） |
| 双态 | 常驻 | 有 | 接近 0（等事件） |

### 统一联系人中心说明

官方设计**刻意不做**跨来源身份映射。本项目新增这一层，因为「同一个人在哪都算白名单」是刚需。

```json
{
  "uid": "owner",
  "identities": {
    "github": ["<账号>"],
    "email": ["<地址>"],
    "qq": ["<号码>"],
    "wecom": ["<账号>"],
    "feishu": ["<open_id>"]
  },
  "policy": {
    "canRequest": true,
    "canProactive": false
  }
}
```

### 自主权限为什么逐项拆

**「允许它自主」不是一个是非题，是十几个是非题。**

| 权限 | 风险 |
|---|---|
| 自主接推断请求 | 可能做你不想要的事 |
| 自主装插件 | 可能装进不可信代码 |
| 自主改自己代码 | 可能改坏 |
| 自主发消息 | 可能说错话 |
| 自主删文件 | 不可逆 |

**建议**：先全关，用一周观察，再逐项开。

### 「隔离进程环境变量」为什么重要

这个插件会修改进程的 `PATH`，把 `gh` 和 `lark-cli` 的包装脚本插到最前。

**融合版下，这会影响同进程的其它插件**。开启隔离开关后，它只在内部使用自己的环境，不污染全局。

**融合版必须开这一项。**
